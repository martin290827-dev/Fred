# Fred

Personal dashboard PWA. Hosted on GitHub Pages (static only, public repo).

## Rules
- Plain HTML, CSS and JavaScript. No build step, no framework, unless I ask.
- The repo is PUBLIC. NEVER put API keys, places, dates, trips, names or any personal data in code, comments, tests or commit messages. Personal values are entered in the app (Settings) and live in the browser (localStorage).
- NEVER put API keys or personal data in the code or the repo. Keys live in the browser (localStorage) via Settings.
- All internet calls happen from the browser. Only use APIs that allow CORS.
- Keep the code simple and readable. Small functions, short comments.
- One feature per session. Do not refactor unrelated code.
- After changing app files, bump `CACHE` in `sw.js` AND every `?v=` number in index.html and in `SHELL` in sw.js (GitHub Pages caches files for 10 minutes). All files share one number.
- Before every push run `node tools/check.js` (SHELL list, `?v=` numbers, every API host in the CSP) and `node tools/test.js` (logic tests without a browser: Sheet sync safety, summaries, meal preview, heatmap bases, AI request settings). Add a test when you change one of these rules.
- Phone and desktop always have the same features. Only the layout may differ.
- The app speaks GERMAN (all visible text, titles, aria-labels, messages). Code, comments, identifiers and this file stay English; labels quoted below may still show the old English wording. Dates use 'de-AT' (e.g. "25. Okt."), numbers use German style via 'de-DE' (`fmtN` "2.283", `fmtKg` / `fmtD` "106,0"). Values that are STORED stay English so old data keeps working: Sheet tab and column names, tolerance levels and symptoms (`TOL_LEVELS`, `TOL_SYMPTOMS`; shown via `TOL_LEVELS_DE`, `symDe`), poker games (`POKER_GAMES`; shown via `gameDe`), class names and keys. AI system prompts stay English; every AI request asks for the answer in German ('de-AT (Deutsch)').

## Files
- index.html, style.css: page and styles (layout and components). m3.css: the Material 3 (Google) look for the whole app, loaded right after style.css; it only overrides colours, surfaces, shapes, controls and type weights. theme.js runs first (frame check).
- app.js: helpers (`store`, `el`, `$`), banners, events list, currency, dates, shopping, notes, settings, backup, layout and tabs, wiring (`init()` on DOMContentLoaded), chart tooltips.
- weather.js: Weather card, second place, current location, places edited in the card (loaded right after app.js).
- markets.js: tickers, ticker editor, market news, sparklines, earnings dates (loaded after weather.js).
- gcal.js: Google Calendar and sign-in. sync.js: hidden Drive sync file and `driveFetch`. sheets.js: Google Sheet "Fred Daten" (loaded last).
- food.js: Food, Trends, Weight & Goal, tolerance, AI helpers. tips.js: Tips card. weekly.js: Weekly card. poker.js: Poker card.
- archive.js: hidden history for later analysis, not shown in any card (loaded after food.js, before recovery.js).
- recovery.js: Recovery card and Sleep card (Whoop CSV import of up to three files, own provider-neutral score, sparklines; loaded after archive.js, uses its CSV reader).
- now.js: Now and Patterns cards (loaded after heatmap.js; `initNow()` runs from app.js init).
- nsum.js: Nutrition Summary card (loaded after now.js; `initNutSum()` runs from app.js init, `renderFood` also calls `renderNutSum`).
- cockpit.js: Cockpit card (loaded after nsum.js; `renderCockpit()` is called from `renderRecovery` and when workouts arrive from the Sheet).
- heatmap.js: Heatmap card (loaded after weekly.js; `initHeat()` runs from app.js init).
- sw.js: offline cache.

## Current features
Food cards: Food (input, stacked rings, meals), Weight & Goal (in Body: weight, waist, BMI, tolerance), Trends (range W/M/3M: 7-day check on W, calories, protein, carbs, fat, weight); all rendered by renderFood().
Sparklines (30 days; Binance for crypto, Twelve Data key for stocks), second weather place (click to switch), optional current location as main weather place (per device, not synced; coords rounded to ~1 km; name via BigDataCloud reverse-geocode-client), events (read from Google Calendar, nothing typed in), card order and hiding (Layout button), settings backup as a file (Download / Load), weather (Open-Meteo), tickers (Binance for crypto with prefix `c:`, Finnhub for stocks), Google Calendar view ("Tasks & reminders": timed appointments; all-day and multi-day items show under Events), shopping list (edit), notes (free text, autosave, in backup, share button: system share sheet, e.g. Apple Notes; clipboard fallback), earnings dates of stock tickers (Finnhub, under Events), market news card (full width; Finnhub company news for stocks, crypto feed matched by coin name; headlines only), floating Google Reconnect button (`gPopUpdate` in gcal.js: bottom of the screen over every card, shown when the one-hour session is over or a permission is missing, hidden once connected; × hides it until the next session). 3 minutes before the hour is over Fred renews the token without a window (`gEndTimer` → `gSilentToken`); only if Google refuses does the button show at the end of the hour, food diary card (food.js: dictated text, calories by Claude API with the user's own key or '... kcal' in the text, weight, 30-day charts; saved in the Sheet "Fred Daten"), sync between devices via a hidden file in Google Drive appDataFolder (sync.js, scope drive.appdata; newest change per setting wins; ), add/edit/delete Google items from Fred (Google is the only copy; repeating items: only this or whole series; birthdays read-only), day/night mode follows the device (no button), countdowns, USD/EUR/MXN/GBP/CHF/JPY/CNY/PHP converter (default pair in Settings). Nutrition targets (calorie goal, protein/carbs/fat rings, 7-day check).

- Recovery card (score, HRV, resting HR, import) and Sleep card (duration, stages, debt, bedtime rhythm), traffic-light charts: manual import of a Whoop CSV (Physiologische Zyklen). Fred computes its own score from HRV and resting HR (deviation from a rolling 30-night baseline) minus sleep debt, not Whoop's proprietary recovery. Data in localStorage key `whoop` (synced, in backup). Only the CSV parser is provider-specific.

- Raw Whoop history (archive.js + `shRawFlush` in sheets.js): all three Whoop CSVs (all columns, naps included) are upserted by key into the tabs "Whoop Zyklen / Schlaf / Training" of the Sheet "Fred Daten"; this history only grows. Changes wait in a local queue (`arcQueue`, not synced, not in backup) until Google is connected. The old JSON file "Fred Archiv Daten.json" was copied in once (`arcMigrate`). Meals, weight and poker are NOT archived separately any more (`ARC_OFF`): their only cloud copy is their own tab in "Fred Daten" (Google Sheets keeps a version history), plus the backup file. Status line in the Recovery card, Data.

- AI models (food.js): `AI_MODEL` = Haiku 5.5 for estimates, sugar, cook ideas, weekly text, tolerance and the event scan; `TIPS_MODEL` = Sonnet 5.5 for "Missing today" and the Body / Nutrition Summary tips. Haiku 4.5 is no longer used. `aiBody` / `AI_OPTS` set the request per model: Haiku 5.5 with `thinking: disabled` and effort `low` (its default adaptive thinking counts against max_tokens and cut answers off), max_tokens x2; Sonnet 5.5 with effort `medium`, max_tokens x4 as room for thinking (only used tokens are billed). `aiJSON` retries a failed Haiku call once with Haiku 5.5 after 1.5 s (not on key errors); `aiTips` falls back from Sonnet to Haiku 5.5. A `refusal` stop reason is shown as an error. Estimate errors show in the meal row.
- Macros: the Trends charts show a day only if EVERY meal of that day has protein, carbs and fat. `fillMacros` / `backfillMacros` fill missing ones at start (30 per start); meals with own kcal keep them and the estimate is scaled to it. The hover text of an empty bar names the meals without macros (`missingNote`).
- Food meal row: text (up to 3 lines, field limit 1500 characters), buttons at its right, below it time, kcal and P/C/F/S chips. The meal list shows the last two meals, the rest scrolls. Editing (pencil or tap on the text, `foodEditRow`): a full-width text box that grows with the text (`autoGrow`, no sideways scrolling, 16 px so iOS does not zoom), below it time, kcal, Save and Cancel; Enter saves, Escape cancels; while editing the list shows the whole edit row.

## Storage
- Sheet sync cost (sheets.js): the minute timer first asks Drive only for the Sheet's `modifiedTime` (`shModTime`); when nothing changed here (`shDirty`, set by `shTouch`) or there (`shMod`) and the last full sync is under 10 minutes old (`shCanSkip`), the full download is skipped. Coming back to Fred (visibilitychange), start and local changes always run a full sync.
- Performance with years of data: `dayTotals` uses meals grouped by day (`foodByDay`, rebuilt when the list or its length changes, dropped after the current task and in `saveFood`); number and date formatting use one `Intl` formatter each (`NF0`, `NF1`, `DF_SHORT`); the 7-day weight average is a sliding window. Measured with ~3 years of synthetic data: `renderFood` ~35 ms (was ~300 ms).
- Sheet sync safety (sheets.js): all tabs are read in ONE `values:batchGet` per sync (`shReadAll`). A tab is written in ONE values.update (`shPutTab`): old rows and columns beyond the new data are overwritten with empty cells (`shPad`, sizes from the read), no separate clear, so a write is all or nothing and never leaves an empty tab (a clear range like A5:ZZ could also exceed the grid). A tab that is completely blank (no header row) while it had rows at the last sync is treated as a failed write, not as "everything deleted": this device's rows are written back and a banner names the tab (`shLost`, `shWarn`). Deleting everything in Fred leaves the header row, so that still syncs as a delete.
- Storage full: `store.set` shows one banner per session when the browser cannot save (`storeFull` in app.js) instead of failing silently.
- Everything except notes and keys lives in the Google Sheet "Fred Daten" (sheets.js, one tab per set): tickers (with order), shopping list, food, weight, poker, daily Whoop values, raw Whoop history, and a settings tab (goals, tips, tolerance, weekly texts, weather places, default currencies, card layout per kind of device: touch = phone, else desktop). The browser only keeps a working copy. Needs the Google Sheets API enabled in the user's Cloud project.
- Food tracks sugar (total sugar, limit 10 % of calories); older meals get their sugar estimated once.
- AI cost (food.js `aiTrack`, shown under the Anthropic key in Settings): every API answer adds its tokens (`usage`) per month and model to `aiUse`; cost = tokens x `AI_PRICES` (USD per million tokens, checked 17 Oct 2026; update the table when prices change). Each kind of device (phone / desktop) writes only its own row `aiuse-<kind>` in the Sheet tab "Einstellungen" and reads the other one as `aiUseOther`, so the total covers both. Only tokens are stored, no prompts or answers. Counting starts at `since`; earlier spending is not included.
- Security: `index.html` has a Content-Security-Policy. A new API host must be added to `connect-src`, a new script must be a file (no inline scripts). `theme.js` runs first (frame check).
- Tickers: an index is followed through its ETF (SPY, QQQ, DIA, IWM) because the free sources have no index levels. Old symbols like SPX are mapped once (`INDEX_ALIAS`). Index ETFs get no company news or earnings.
- Weekly summaries are written to the Sheet tab "Weekly Review" (one readable row per week: summary, went well, next week).
- Cheat day: switch on in Settings (`nutri.cheatOn`); Food then lets you mark any of the last 7 days (also afterwards), strictly one per Mon–Sun week (`nutri.cheatDays`). Marked days are shown with a diamond in the trend charts; totals and summaries still count them (the Nutrition Summary AI is told about them).
- Card "Health & Nutrition Tips" (`tips.js`, `#card-tips`, in Nutrition): "Missing today" (AI from today's meals, `loadAll`, sent when meals or the time of day changed or on the ↻ button `#tips-refresh`) and "What shall I cook?" (AI from foods at home and what is left today, separate request). Results are kept in `gaps` and `cook` in this browser only. The old 14-day tips were removed (the Nutrition Summary covers 7 / 15 / 30 days); the `tips` setting is only kept so the synced settings row stays valid.
- Before you eat (food.js `knownMeal`, `mealPreview`, `mealIdeas`; now.js `nowFits`; no AI, no cost): while typing a meal (Food field and quick add) a line shows its calories and where today would stand ("≈ 900 kcal → today 2,650 of 2,200"), red when over; known = same text logged before, or "... kcal" in the text. Quick-add chips show their kcal and get a red ring when they would go over. From 14:00 the Food row in Now lists up to 3 meals from the last 60 days (not the ones already eaten today) that still fit the calories left (150 kcal or more, most protein per kcal first), or says the day is done.
- Tasks and Events are one card "Tasks & Events" with ONE list sorted by day (events first on a day, then timed items). The + opens a form with a Task | Event switch. Touch: swipe a row to the left (`gSwipeDelete` in gcal.js) to delete; it asks "Delete?" in the row (same as the trash button). Read-only items (birthdays) have no swipe.
- Heatmap card (`heatmap.js`, `#card-heat`, wide, right after Tickers): one tile per ticker, colour = change over 1D / 1W (7 days) / 1M (30 days) / 3M / 6M / YTD / 1Y (365 days), grey = small move, full red/green at 3 / 10 / 20 / 30 / 40 / 40 / 50 % (square-root scale, `heatStrength`); buttons Refresh and Size: Equal | Move (wider tiles for bigger moves); "Snapshot taken" = time of the last quote load. Price and 1D come from `loadQuotes` (`lastQuotes`, `lastQuotesAt`); the other periods use bases from daily closes (Binance for crypto, Twelve Data for stocks, max 6 stock downloads per minute, cached per day in `heatBase`, only the bases are kept). Without a Twelve Data key stocks show 1D only. Period and size are per device (`heat`, not synced).
- Group tabs (app.js `TAB_GROUPS`, `#tabbar`; phone: bottom bar, desktop: row in the header, the old jump chips are gone): the bar groups the cards (Today: Now, Weather, Tasks & Events, Shopping, Notes; Markets: Tickers, Heatmap, News; Nutrition: Nutrition Summary, Food, Tips, Trends, Weekly, Patterns; Body: Cockpit, Body Summary, Weight & Goal, Recovery, Sleep, Sleep Habits; Tools: Currency, Poker; Timer, Calculator and world clocks were removed because iOS has them); only the active group shows, the last tab is kept per device (`tab`). Phone and desktop both show one group at a time. Cards in a group have the same height (`--card-h` 412 px, 520 px for Nutrition, 700 px for Body via `body[data-tab]`; longer content scrolls inside); only the Heatmap on the phone is as high as its tiles. Desktop (6 columns): Now is a full row (auto height, 4 tiles) on the desktop; on the phone it is as high as every other card, the 4 rows stack and scroll inside; the extra detail lines `.now-x` show on both, Weather, Tasks and Shopping share the second row, Notes span 6, Heatmap and Poker span 4, News spans 6, the rest 2, so every row is full. Card order follows `TAB_GROUPS` (`mig.tabOrder2` reset the saved order once). The Market Hours card was removed. Layout (order / hide) works inside a group; a new card needs an entry in `TAB_GROUPS` (otherwise it lands in Tools).
- Cards "Now" and "Patterns" (`now.js`, `#card-now`, `#card-patterns`; no AI, no cost): Now = next appointment, calories left with protein still to go, recovery score with advice and sleep debt, biggest ticker move today; each row opens its card. Patterns = median-split comparisons: sleep vs same-day kcal, weeks with more vs less protein vs weight change; shown only with enough data (8 days / 6 weeks), cheat days are left out, differences under 100 kcal / 0.2 kg count as no link. - Sync freshness (`syncAge` / `syncLineUpdate` in sheets.js; `shOkAt` = time of the last good Sheet sync, this device only): a line under the Food heading (`#sync-age`: "Synced 3 min ago", orange when older than 10 min or the Google session is over) and an "Open" row in Now (no weight for 7 days, no Whoop data for 7 days, no meal after 14:00, stale sync; only shown when something is open; full row on desktop).

- Card "Body Summary" (`now.js` `renderBodySum`, `#card-bodysum`, first in Body, full row on desktop, fixed height 340 px with the content scrolling inside): `bsFacts` takes the n newest nights (range buttons, see below) and the n nights before them; the list (`BS_ROWS`: score, HRV, resting HR, sleep, debt, efficiency, deep sleep, bedtime spread, workouts) shows "Last n", "Before" and the change (better / worse / same, with a step per measure). Summary sentence and 3 to 5 tips come from the AI (`bsLoadAi`, `TIPS_MODEL` through `aiTips`; numbers only; one request per range and new newest night or on the ↻ button `#bs-refresh`; earlier tip titles go in so tips are not repeated). Without a key, while it loads, or on an error the fixed rules (`bsTips`) show instead, with a note. After an error there is no automatic retry for that night. Needs a baseline (about 14 nights).
- Range buttons 7 / 15 / 30 days in Body Summary and Nutrition Summary (`rangeSeg` in now.js; `bsRange`, `nsRange`, per device, not synced): the last n nights / full days against the n before, same look as the Recovery buttons. The earlier period needs at least 4 nights (Body) or 3 logged days (Nutrition); otherwise a note says how many it has. The buttons stay at the top while the card scrolls. AI answers are kept per range (`bodyAi2`, `nutAi2`, this browser only): switching to a range without an answer for the newest night makes ONE request (max 3 per day and card); for 15 / 30 days the AI gets day lines for the current period and only averages for the earlier one.
- Waist and BMI (food.js `waist`, `saveTodayWaist`, `waForm`, `bmiOf`, `waistRef`; Sheet tab "Waist" in sheets.js, also in the backup): the Weight & Goal card (now in Body, two cards per row on the desktop in Body and Nutrition so rows stay full) has a second row for the waist in cm, entered about once a week; its change is against the entry before, and the sex in Settings gives the risk limits (men 94 / 102 cm, women 80 / 88 cm). BMI = weight / height squared (height in Settings, none stored in code) and shows next to the weight. Nutrition Summary has the rows BMI and Waist (BMI follows the weight goal, a smaller waist is better). "Open" in Now reminds after 7 days without a waist entry.

- Tolerance (food.js `tolRow`, `tolHistory`, `tolCard`, `loadTolerance`; inside the Weight & Goal card): meals of the last 3 days get a level (OK / Mild / Medium / Strong) and symptom chips. Below: the button "What do I not tolerate?" (AI over 90 days of meals, needs 3 flagged meals and the Anthropic key) gives up to 5 foods that may not agree and up to 5 that seem well tolerated (`tol.list`, `tol.safe`, `tol.n` = number of reactions it was based on; a note says when reactions changed since), and `tolHistory` lists ALL reactions of 90 days with a count per symptom (no AI). - Card "Nutrition Summary" (`nsum.js`, `#card-nutsum`, first in Nutrition, full row on desktop, fixed height 340 px with the content scrolling inside; same look as Body Summary): the last n FULL days (range buttons; today does not count) against the n days before: days logged, calories, protein, carbs, fat, sugar per day (macros only from days where every meal has them) weight, BMI and waist, each with better / worse / same (`nsBad`: calories, carbs, fat = closer to target is better, protein = reaching the target, sugar = less, weight = toward the goal). - Card "Cockpit" (`cockpit.js`, `#card-cockpit`, first in Body, full row on desktop, auto height; no AI, no cost): the newest uploaded WEEK (7 calendar days ending at the newest night; data arrive about once a week, so there is no "today" view) against the normal = the 30 nights before it (`ckFacts`, pure, tested). Three rings (`ckRing`): Sleep = hours / sleep need (8 h when the device gives none; green from 85 %, orange from 70 %), Recovery = Fred score, Load = training minutes of the week (full ring = twice the normal week, a tick marks the normal; normal = the 28 days before / 4). Below: HRV, resting HR, breathing rate (neutral; a rise of 1 /min or more is red), sleep, deep sleep, efficiency, workouts, each "week vs normal" with an arrow (`ckJudge`). Only provider-neutral values: Whoop strain and Whoop recovery are NOT used. Look: Material 3: three separate rings (`ckRing`; colour = status: green / yellow / red, load in blue), each with label, normal value and a tonal status chip (`ckChip`; Google colours in `--ck-*` variables, own dark values), tonal tiles with a line icon (`CK_ICONS`), the value in light weight, a chip with the change as an amount and the normal value. No Google font (the CSP allows no outside fonts; Android uses Roboto anyway).
- Device per night (`dev` in `whoop`, Sheet column `dev`; `rcDev` in recovery.js, missing = 'whoop'): every importer sets its device name. The Fred-Score baseline, the Cockpit normal and the Body Summary compare only nights of the SAME device, because HRV and other values differ between wearables. After a switch the Cockpit shows "Kalibrierung" until 7 nights of the new device exist before the shown week. A new wearable only needs a new importer that writes the same neutral fields plus its `dev`.
