# Fred

Personal dashboard PWA. Hosted on GitHub Pages (static only, public repo).

## Rules
- Plain HTML, CSS and JavaScript. No build step, no framework, unless I ask.
- The repo is PUBLIC. NEVER put API keys, places, dates, trips, names or any personal data in code, comments, tests or commit messages. Personal values are entered in the app (Settings) and live in the browser (localStorage).
- NEVER put API keys or personal data in the code or the repo. Keys live in the browser (localStorage) via Settings.
- All internet calls happen from the browser. Only use APIs that allow CORS.
- Keep the code simple and readable. Small functions, short comments.
- One feature per session. Do not refactor unrelated code.
- After changing app files, bump `CACHE` in `sw.js` AND the `?v=` number on style.css, app.js, gcal.js, sync.js, food.js and recovery.js (and in `SHELL` in sw.js) in index.html (GitHub Pages caches files for 10 minutes).
- Before every push run `node tools/check.js`. It checks the SHELL list, all `?v=` numbers and that every API host is in the CSP.
- Phone and desktop always have the same features. Only the layout may differ.

## Files
- index.html, style.css: page and styles. app.js: everything else. gcal.js: Google Calendar (loaded after app.js; `init()` runs on DOMContentLoaded).
- archive.js: hidden history for later analysis, not shown in any card (loaded after food.js, before recovery.js).
- recovery.js: Recovery card and Sleep card (Whoop CSV import of up to three files, own provider-neutral score, sparklines; loaded after archive.js, uses its CSV reader).
- now.js: Now and Patterns cards (loaded after heatmap.js; `initNow()` runs from app.js init).
- nsum.js: Nutrition Summary card (loaded after now.js; `initNutSum()` runs from app.js init, `renderFood` also calls `renderNutSum`).
- heatmap.js: Heatmap card (loaded after weekly.js; `initHeat()` runs from app.js init).
- sw.js: offline cache.

## Current features Food is split into three cards: Food (input, stacked rings, meals), Health (goal with current weight and 3 key numbers, daily AI tips from the last 7 days; weight is entered in Settings), Trends (range W/M/3M: 7-day check on W, calories, protein, carbs, fat, weight); all rendered by renderFood().
Sparklines (30 days; Binance for crypto, Twelve Data key for stocks), second weather place (click to switch), optional current location as main weather place (per device, not synced; coords rounded to ~1 km; name via BigDataCloud reverse-geocode-client), events (read from Google Calendar, nothing typed in), card order and hiding (Layout button), settings backup as a file (Download / Load), weather (Open-Meteo), tickers (Binance for crypto with prefix `c:`, Finnhub for stocks), Google Calendar view ("Tasks & reminders": timed appointments; all-day and multi-day items show under Events), shopping list (edit), notes (free text, autosave, in backup, share button: system share sheet, e.g. Apple Notes; clipboard fallback), earnings dates of stock tickers (Finnhub, under Events), market news card (full width; Finnhub company news for stocks, crypto feed matched by coin name; headlines only), floating Google Reconnect button (`gPopUpdate` in gcal.js: bottom of the screen over every card, shown when the one-hour session is over or a permission is missing, hidden once connected; × hides it until the next session), food diary card (food.js: dictated text, calories by Claude API with the user's own key or '... kcal' in the text, weight, 30-day charts, mirrored to two Google Sheets via drive.file), sync between devices via a hidden file in Google Drive appDataFolder (sync.js, scope drive.appdata; newest change per setting wins; ), add/edit/delete Google items from Fred (Google is the only copy; repeating items: only this or whole series; birthdays read-only), day/night mode follows the device (no button), countdowns, USD/EUR/MXN/GBP/CHF/JPY/CNY/PHP converter (default pair in Settings). Nutrition targets (calorie goal, protein/carbs/fat rings, 7-day check).

- Recovery card (score, HRV, resting HR, import) and Sleep card (duration, stages, debt, bedtime rhythm), traffic-light charts: manual import of a Whoop CSV (Physiologische Zyklen). Fred computes its own score from HRV and resting HR (deviation from a rolling 30-night baseline) minus sleep debt, not Whoop's proprietary recovery. Data in localStorage key `whoop` (synced, in backup). Only the CSV parser is provider-specific.

- Hidden history (archive.js): one JSON file in Drive ("Fred Archiv Daten.json", scope drive.file) is the real archive; Sheets "Fred Archiv Zyklen / Schlaf / Training / Essen / Gewicht" are generated from it. All three Whoop CSVs (all columns, naps included) and every meal and weight are upserted by key; history only grows. Only an explicit delete of a meal removes it. Missing entries after a sync are never treated as deleted. Changes wait in a local queue (`arcQueue`, not synced, not in backup) until Google is connected. Status line in the Recovery card, Daten.

- AI models (food.js): `AI_MODEL` = Haiku 5.5 for estimates, sugar, cook ideas, weekly text, tolerance and the event scan; `TIPS_MODEL` = Sonnet 5.5 for the health tips only. `aiJSON` gives the default model 3x the token budget (thinking counts against max_tokens) and falls back to Haiku 4.5 (`AI_FALLBACK`) on any error except the key. Estimate errors show in the meal row.
- Macros: the Trends charts show a day only if EVERY meal of that day has protein, carbs and fat. `fillMacros` / `backfillMacros` fill missing ones at start (30 per start); meals with own kcal keep them and the estimate is scaled to it. The hover text of an empty bar names the meals without macros (`missingNote`).
- Food meal row: text (up to 3 lines, field limit 1500 characters), buttons at its right, below it time, kcal and P/C/F/S chips. The meal list shows the last two meals, the rest scrolls.

## Storage
- Everything except notes and keys lives in the Google Sheet "Fred Daten" (sheets.js, one tab per set): tickers (with order), shopping list, food, weight, poker, daily Whoop values, raw Whoop history, and a settings tab (goals, tips, tolerance, weekly texts, weather places, default currencies, card layout per kind of device: touch = phone, else desktop). The browser only keeps a working copy. Needs the Google Sheets API enabled in the user's Cloud project.
- Food tracks sugar (total sugar, limit 10 % of calories); older meals get their sugar estimated once.
- AI cost (food.js `aiTrack`, shown under the Anthropic key in Settings): every API answer adds its tokens (`usage`) per month and model to `aiUse`; cost = tokens x `AI_PRICES` (USD per million tokens, checked 17 Oct 2026; update the table when prices change). Each kind of device (phone / desktop) writes only its own row `aiuse-<kind>` in the Sheet tab "Einstellungen" and reads the other one as `aiUseOther`, so the total covers both. Only tokens are stored, no prompts or answers. Counting starts at `since`; earlier spending is not included.
- Security: `index.html` has a Content-Security-Policy. A new API host must be added to `connect-src`, a new script must be a file (no inline scripts). `theme.js` runs first (frame check).
- Tickers: an index is followed through its ETF (SPY, QQQ, DIA, IWM) because the free sources have no index levels. Old symbols like SPX are mapped once (`INDEX_ALIAS`). Index ETFs get no company news or earnings.
- Weekly summaries are written to the Sheet tab "Weekly Review" (one readable row per week: summary, went well, next week).
- Cheat day: switch on in Settings (`nutri.cheatOn`); Food then lets you mark any of the last 7 days (also afterwards), strictly one per Mon–Sun week (`nutri.cheatDays`). Marked days are left out of the AI tips and shown with a diamond in the trend charts; totals still count them.
- Card "Health & Nutrition Tips" (the card before it is "Weight & Goal") (`tips.js`, `#card-tips`): the 14-day tips (moved out of Health), "Missing today" (AI from today's meals) and "What shall I cook?" (AI from foods at home and what is left today). Results are kept in `gaps` and `cook` in this browser only. The 14-day tips and "Missing today" share ONE request (`loadAll` in tips.js, one JSON answer with the keys `tips` and `today`); only the parts that are due are sent (tips once a day or on ↻, today's check when meals or the time of day changed). One refresh button (`#tips-refresh`) sits in the card heading and refreshes both; `loadTips` is a thin wrapper; the cook question stays a separate request.
- Tasks and Events are one card "Tasks & Events" with ONE list sorted by day (events first on a day, then timed items). The + opens a form with a Task | Event switch. Touch: swipe a row to the left (`gSwipeDelete` in gcal.js) to delete; it asks "Delete?" in the row (same as the trash button). Read-only items (birthdays) have no swipe.
- Heatmap card (`heatmap.js`, `#card-heat`, wide, right after Tickers): one tile per ticker, colour = change over 1D / 1W (7 days) / 1M (30 days) / YTD, grey = small move, full red/green at 3 / 10 / 20 / 40 % (square-root scale, `heatStrength`); buttons Refresh and Size: Equal | Move (wider tiles for bigger moves); "Snapshot taken" = time of the last quote load. Price and 1D come from `loadQuotes` (`lastQuotes`, `lastQuotesAt`); the other periods use bases from daily closes (Binance for crypto, Twelve Data for stocks, max 6 stock downloads per minute, cached per day in `heatBase`, only the bases are kept). Without a Twelve Data key stocks show 1D only. Period and size are per device (`heat`, not synced).
- Group tabs (app.js `TAB_GROUPS`, `#tabbar`; phone: bottom bar, desktop: row in the header, the old jump chips are gone): the bar groups the cards (Today: Now, Weather, Tasks & Events, Shopping, Notes; Markets: Tickers, Heatmap, News; Nutrition: Nutrition Summary, Food, Tips, Trends, Weekly, Patterns; Body: Body Summary, Weight & Goal, Recovery, Sleep, Sleep Habits; Tools: Currency, Poker; Timer, Calculator and world clocks were removed because iOS has them); only the active group shows, the last tab is kept per device (`tab`). Phone and desktop both show one group at a time. Cards in a group have the same height (`--card-h` 412 px, 520 px for Nutrition, 700 px for Body via `body[data-tab]`; longer content scrolls inside); only the Heatmap on the phone is as high as its tiles. Desktop (6 columns): Now is a full row (auto height, 4 tiles) on the desktop; on the phone it is as high as every other card, the 4 rows stack and scroll inside; the extra detail lines `.now-x` show on both, Weather, Tasks and Shopping share the second row, Notes span 6, Heatmap and Poker span 4, News spans 6, the rest 2, so every row is full. Card order follows `TAB_GROUPS` (`mig.tabOrder2` reset the saved order once). The Market Hours card was removed. Layout (order / hide) works inside a group; a new card needs an entry in `TAB_GROUPS` (otherwise it lands in Tools).
- Cards "Now" and "Patterns" (`now.js`, `#card-now`, `#card-patterns`; no AI, no cost): Now = next appointment, calories left with protein still to go, recovery score with advice and sleep debt, biggest ticker move today; each row opens its card. Patterns = median-split comparisons: sleep vs same-day kcal, weeks with more vs less protein vs weight change; shown only with enough data (8 days / 6 weeks), cheat days are left out, differences under 100 kcal / 0.2 kg count as no link. Patterns sits in Nutrition. Tab switches fade in (`tab-in`).
- Places and tickers are edited in their cards (pencil / +), not in Settings. The converter remembers the last pair.
- Notes and API keys / Client ID sync through the hidden Drive file (sync.js). The Client ID cannot live in the Sheet: it is needed to sign in first.
- Sync freshness (`syncAge` / `syncLineUpdate` in sheets.js; `shOkAt` = time of the last good Sheet sync, this device only): a line under the Food heading (`#sync-age`: "Synced 3 min ago", orange when older than 10 min or the Google session is over) and an "Open" row in Now (no weight for 7 days, no Whoop data for 7 days, no meal after 14:00, stale sync; only shown when something is open; full row on desktop).
- Quick add (food.js `addMeal`, `openQuick`, `initQuick`; `#btn-quick` "+ Meal" in the header, `#dlg-quick`): works on every tab; tap one of the 8 most recent distinct meals to add it again, or type a new one. `addMeal` is also used by the Food form.
- Card "Body Summary" (`now.js` `renderBodySum`, `#card-bodysum`, first in Body, full row on desktop, fixed height 340 px with the content scrolling inside): works on WEEKS because the Whoop data is uploaded once a week. `bsFacts` takes the 7 newest nights and the 7 nights before them; the list (`BS_ROWS`: score, HRV, resting HR, sleep, debt, efficiency, deep sleep, bedtime spread) shows this week, last week and the change (better / worse / same, with a step per measure). Summary sentence and 3 to 5 tips come from the AI (`bsLoadAi`, `TIPS_MODEL` through `aiTips`; both weeks are sent as numbers only; one request per new newest night or on the ↻ button `#bs-refresh`; kept in `bodyAi`, this browser only; earlier tip titles go in so tips are not repeated). Without a key, while it loads, or on an error the fixed rules (`bsTips`, based on the week) show instead, with a note. After an error there is no automatic retry for that night. Needs a baseline (about 14 nights); the comparison needs at least 4 nights in the earlier week.
- Waist and BMI (food.js `waist`, `saveTodayWaist`, `waForm`, `bmiOf`, `waistRef`; Sheet tab "Waist" in sheets.js, also in the backup): the Weight & Goal card (now in Body, two cards per row on the desktop in Body and Nutrition so rows stay full) has a second row for the waist in cm, entered about once a week; its change is against the entry before, and the sex in Settings gives the risk limits (men 94 / 102 cm, women 80 / 88 cm). BMI = weight / height squared (height in Settings, none stored in code) and shows next to the weight. Nutrition Summary has the rows BMI and Waist (BMI follows the weight goal, a smaller waist is better). "Open" in Now reminds after 7 days without a waist entry.
- Workouts (recovery.js `rcWorkoutCols`, `rcWorkoutEntry`, `workouts`; Sheet tab "Workouts", in the backup): the Whoop workouts CSV is read at import into neutral fields (id = start time, day, name, minutes, kcal, average and max heart rate, strain). The columns are found by keywords in their names, because the real export was never seen here; the import message names columns it did not find. Only these two functions are Whoop-specific. Body Summary shows the rows Workouts, Training time and Training energy (week against last week; no better / worse, training volume is not good or bad by itself) and the list "Workouts this week"; the AI gets the workouts too (the AI answer is renewed once when workouts arrive, `bsKey`). No workouts in either week: the rows stay hidden. Needs the workouts file imported once more, older imports were only archived (archive.js).
- Tolerance (food.js `tolRow`, `tolHistory`, `tolCard`, `loadTolerance`; inside the Weight & Goal card): meals of the last 3 days get a level (OK / Mild / Medium / Strong) and symptom chips. Below: the button "What do I not tolerate?" (AI over 90 days of meals, needs 3 flagged meals and the Anthropic key) gives up to 5 foods that may not agree and up to 5 that seem well tolerated (`tol.list`, `tol.safe`, `tol.n` = number of reactions it was based on; a note says when reactions changed since), and `tolHistory` lists ALL reactions of 90 days with a count per symptom (no AI). A food only counts as tolerated if reactions are flagged reliably.
- Card "Nutrition Summary" (`nsum.js`, `#card-nutsum`, first in Nutrition, full row on desktop, fixed height 340 px with the content scrolling inside; same look as Body Summary): the last 7 FULL days (today does not count) against the 7 days before: days logged, calories, protein, carbs, fat, sugar per day (macros only from days where every meal has them) and weight, each with better / worse / same (`nsBad`: calories, carbs, fat = closer to target is better, protein = reaching the target, sugar = less, weight = toward the goal). Cheat days count in the numbers; the AI is told about them. Summary sentence and 3 to 5 tips from the AI (`nsLoadAi`, `TIPS_MODEL` through `aiTips`, one request per day or on the \u21bb button `#ns-refresh`, kept in `nutAi`, this browser only; meals text of the 14 days is sent, nothing else). Without a key, while loading or on an error the fixed rules (`nsTips`) show. Needs 2 logged days this week; the comparison needs 3 in the week before.
